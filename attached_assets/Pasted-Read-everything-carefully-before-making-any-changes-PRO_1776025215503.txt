PROJECT OVERVIEW:

This project is called CosmicTiers.

It is a full-stack Minecraft PvP tier system designed for cracked Minecraft players.

Players can:
- Register via Discord bot
- Get tested by staff
- Receive a tier ranking
- View leaderboard and profiles on the website

---

SYSTEM ARCHITECTURE:

The project is divided into 3 main services:

1. BACKEND
- Folder: backend/
- Tech: Node.js + Express
- Handles:
  - API routes
  - Database operations
  - Game modes
  - Tier system logic
- Hosted on Render (Web Service)

2. DISCORD BOT
- Folder: bot/
- Tech: Node.js (Discord.js)
- Handles:
  - Commands (/register, /test, /result, /tier, /edit-profile)
  - Staff interactions
  - Assigning tier roles
  - Sending result messages
- Communicates with backend API
- Hosted on Render (Web Service)

3. WEBSITE
- Folder: website/
- Tech: React + Vite
- Handles:
  - Leaderboard
  - Player cards
  - Player profiles
  - Tier tester UI
- Fetches data from backend API
- Hosted on Render (Static Site)

---

DATABASE:

- PostgreSQL (Neon or similar)
- Stores ALL persistent data:
  - users
  - profiles
  - tiers
  - game modes
  - results
  - skins

IMPORTANT:
- No data should rely on local files
- Everything must persist after redeploy

---

HOW THE SYSTEM WORKS:

Flow:
User → Discord Bot → Backend → Database → Website

1. User registers via Discord bot
2. Backend creates user in database
3. Staff tests player using bot commands
4. Bot sends results to backend
5. Backend stores:
   - tier
   - points
   - game mode
6. Website fetches and displays data

---

TIER SYSTEM:

- Each game mode has its own tier ranking
- Staff assigns tiers using bot commands
- Backend stores:
  - player tier
  - points
  - game mode
- Bot:
  - creates and assigns Discord roles
- Website:
  - displays tier in leaderboard and profile

---

GAME MODE SYSTEM:

- Multiple PvP modes exist:
  - Nodebuff
  - Boxing
  - Nethpot
  - Sword-PvP

- Each mode has:
  - separate leaderboard
  - separate stats
  - separate tiers

- IMPORTANT STRUCTURE:

Each mode uses:
- id (internal): lowercase, no spaces (e.g. "nodebuff")
- name (display): formatted (e.g. "Nodebuff")

Example:
- id: "swordpvp"
- name: "Sword-PvP"
